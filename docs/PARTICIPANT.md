# Participant and access implementation review

The app entry is `lib/main.dart`; stateful screens are in `lib/participant/`. `EmulatorBackend` configures Auth, Firestore and Functions together, with no production fallback. The real repository subscribes only to the signed-in user's data plus published events/current forms. Controller state keeps intent, pending arrival and confirmed attendance distinct.

Implemented: three intros; real email/password sign-in/sign-up with verification, forgot-password reset and Google Sign-In; five tiered profile steps; event-driven home/session/map; sport filtering and program discovery; RSVP-only Count me in/cancellation; privacy-safe Who's counted in; check-in window/distance preview; strict QR link parsing; once-only prefilled safety details; current-version-only forms; pending/rejected/confirmed states; event feedback; profile form status/attendance history; help; no-app check-in and returning-email verification. The new role view and admin access console implement the latest Workspace request; full coach QR/roster/correction UI and full admin analytics remain later stages.

No email string decides access. Verified Google users without a coach claim are participants. Coach claims, protected revocation gates and event assignment are enforced in both callables and rules. UI switches operate on the same repository/UID; revocation removes coach view immediately while preserving the participant session. The admin lists users by email and invokes audited role/assignment callables, rather than writing claims from the client.

The fake sign-in/social buttons, email-only coach routing, static single-session navigation, decorative QR and immediate fake check-in were retired as authorized. Existing introductory photography, discovery data, location selector, support links and reusable widgets were retained/refactored into `shared_widgets.dart`. The old intent-triggered 30-minute on-device reminder is no longer scheduled; the server's confirmed-attendee +40-minute reminder selects the correct event, using the documented local push double until FCM setup.

Review evidence: `SCREENSHOTS.md` covers S01–S24 and the additional access screens. Fixture screenshots are actual Flutter widget renders with bundled fonts/icons; network map tiles and physical camera preview are disabled for deterministic capture. The app uses real OSM tiles/camera when run normally. A Chrome end-to-end test uses real emulator Auth/Firestore/Functions and verifies Count me in → valid QR → safety details → forms → pending → coach confirms → visible confirmed UI. Physical device OAuth, camera and GPS remain manual validation items.

No Firebase deployment, production data migration, real email delivery, real FCM push or paid service activation occurred. The existing SDK scheduler adapter limitation remains documented in FUNCTIONS.md.
